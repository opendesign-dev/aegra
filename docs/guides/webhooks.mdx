---
title: "Webhooks"
description: "Get a POST callback when a run reaches a terminal state, backed by a transactional outbox."
---

Attach a `webhook` URL to a run and Aegra POSTs the final run payload to it when the run finishes. Delivery goes through a **transactional outbox**, so the notification survives a worker crash between the run finishing and the callback being sent.

## Attaching a webhook to a run

```python
import asyncio
from langgraph_sdk import get_client

async def main():
    client = get_client(url="http://localhost:2026")

    run = await client.runs.create(
        thread_id="<thread_id>",
        assistant_id="agent",
        input={"messages": [{"role": "user", "content": "Summarize this"}]},
        webhook="https://example.com/hooks/aegra",
    )

asyncio.run(main())
```

Crons accept the same field, and the webhook fires for each run the cron creates:

```python
cron = await client.crons.create(
    assistant_id="agent",
    schedule="0 9 * * *",
    input={"messages": [{"role": "user", "content": "Daily report"}]},
    webhook="https://example.com/hooks/aegra",
)
```

The URL is capped at 2048 characters and validated at creation time — an invalid or blocked URL fails the request with a 422 rather than failing silently later.

## Payload

```json
{
  "run_id": "run_abc123",
  "thread_id": "thread_xyz789",
  "assistant_id": "agent",
  "status": "success",
  "run_started_at": "2026-07-27T09:00:00+00:00",
  "run_ended_at": "2026-07-27T09:00:12+00:00",
  "webhook_sent_at": "2026-07-27T09:00:13+00:00",
  "values": { "messages": [] },
  "error": null,
  "metadata": {}
}
```

`values` holds the run's final output (`{}` when there is none) and `error` carries the failure message for a failed run.

## Which terminal states fire

| Status | Fires | Notes |
|---|---|---|
| `success` | Yes | Normal completion |
| `interrupted` | Yes | Human-in-the-loop interrupt, and user-requested cancel |
| `error` | Yes | The graph raised, or a worker died mid-run |
| `timeout` | Yes | The run exceeded `BG_JOB_TIMEOUT_SECS` |

## How delivery works

<Steps>
  <Step title="Enqueue">
    When a run reaches a terminal state, a `pending` row is inserted into the `webhook_deliveries` table **in the same transaction** as the run status update. If the process dies immediately after, the delivery still exists.
  </Step>
  <Step title="Claim">
    A background deliverer polls every 5 seconds and claims up to 100 due rows with `FOR UPDATE SKIP LOCKED`, so replicas take disjoint sets and never double-post the same row.
  </Step>
  <Step title="POST">
    The payload is rebuilt from the persisted run row and POSTed with a per-attempt timeout.
  </Step>
  <Step title="Retry or dead-letter">
    A failed row is rescheduled with exponential backoff. Once `WEBHOOK_MAX_ATTEMPTS` POSTs have failed it moves to `dead`.
  </Step>
</Steps>

A row stuck in `sending` — the deliverer crashed mid-flight — is reclaimed after 120 seconds.

The poll interval, batch size, and stale-reclaim window are fixed constants. Only the retry and signing policy below is configurable.

## Retry behaviour

`WEBHOOK_MAX_ATTEMPTS` counts **total POSTs**: each claim makes exactly one attempt, and the outbox reschedules the row until the count is exhausted. With the default of `3`, a permanently failing endpoint receives 3 POSTs, then the row is dead-lettered.

Between attempts the outbox waits `WEBHOOK_BACKOFF_BASE_SECONDS * 2^attempts`, capped at 5 minutes. With defaults that is roughly 2s, then 4s, then dead.

<Note>
**Delivery is at-least-once.** A receiver that returns 2xx after a network cut can still be retried. Make your handler idempotent — `run_id` is a stable dedupe key.
</Note>

## Signing

Set a secret to have every request carry a [Standard Webhooks](https://www.standardwebhooks.com)-style signature:

```bash
WEBHOOK_SIGNING_SECRET=whsec_your_secret_here
```

Each request then includes:

```
Webhook-Signature: t=1769504413,v1=<hex-hmac-sha256>
```

The HMAC-SHA256 is computed over `{timestamp}.{raw_body}` using the secret. Each attempt is signed with a fresh timestamp, so retries carry valid signatures.

```python
import hashlib
import hmac

def verify(secret: str, header: str, body: bytes) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(","))
    signed = f"{parts['t']}.".encode() + body
    expected = hmac.new(secret.encode(), signed, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, parts["v1"])
```

Reject requests whose timestamp is far from now to blunt replay attacks — Aegra sends the timestamp but does not enforce a window on your behalf.

## SSRF protection

Webhook hosts that resolve to private, loopback, link-local, reserved, multicast, or unspecified addresses are **rejected at run creation** with a 422. The check fails closed: a host that cannot be resolved is treated as private and blocked.

For self-hosted deployments posting to an internal service, opt out:

```bash
WEBHOOK_ALLOW_PRIVATE_IPS=true
```

<Warning>
Only enable this when every caller who can create a run is trusted. With it on, a user-supplied webhook URL can be used to probe your internal network and cloud metadata endpoints.
</Warning>

## Configuration

See the [environment variables reference](/reference/environment-variables#webhooks) for the full table. Set `WEBHOOK_ENABLED=false` to stop both enqueue and delivery.

## Limitations

- **No delivery-status API.** `webhook_deliveries` rows — including `dead` ones — are only visible in the database. There is no endpoint to list, inspect, or replay a failed delivery.
- **Delivery rows are pruned with their run.** `webhook_deliveries` cascades on run deletion, so enabling [run TTL](/guides/retention) also discards dead-letter history for pruned runs.
- **The URL is validated once, at creation.** DNS that later resolves to a private address is not re-checked at delivery time.
- **No per-run retry or signing overrides.** Retry counts, timeouts, and the signing secret are deployment-wide.
